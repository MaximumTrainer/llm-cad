1. Installation

Prerequisites

  • Python 3.11+ — CadQuery requires 3.11 or newer
  • uv — fast Python package manager
  • An MCP host — Claude Code, Claude Desktop, Cursor, or any MCP client

Install from source

git clone https://github.com/MaximumTrainer/llm-cad.git
cd llm-cad
uv sync

This installs all dependencies including CadQuery, trimesh, manifold3d, and the MCP SDK.

Verify the install

uv run python scripts/smoke.py

The smoke test builds a bracket, renders it, validates the mesh, and exports to STL. If it completes without errors, everything is working.

Platform notes CadQuery ships pre-built wheels for Python 3.10–3.13 on Linux x86_64, macOS x86_64/arm64, and Windows x86_64. If uv sync fails with "no matching distribution", check your Python version with python --version and install a supported version via uv python install 3.11.

2. Connecting to an MCP Host

Claude Code

From the repo directory, run:

claude mcp add cad-mcp -- uv run cad-mcp

Or add to your project's .mcp.json:

{
  "mcpServers": {
    "cad-mcp": {
      "command": "uv",
      "args": ["run", "--directory", "/absolute/path/to/llm-cad", "cad-mcp"]
    }
  }
}

Claude Desktop

Add to your claude_desktop_config.json:

{
  "mcpServers": {
    "cad-mcp": {
      "command": "uv",
      "args": ["run", "--directory", "/absolute/path/to/llm-cad", "cad-mcp"]
    }
  }
}

Any stdio MCP client

uv run --directory /path/to/llm-cad cad-mcp

3. Your First Model

Once cad-mcp is connected, ask your LLM to design something. Here's an example conversation:

You: Design a simple wall-mount bracket for a 30mm pipe with two M4 screw holes and 3mm walls.

The LLM will:

  1. Call execute_cad with CadQuery code to build the bracket
  2. Call render_views to see a 4-view PNG preview
  3. Critique the render and refine the code if needed
  4. Call measure to verify the dimensions match your request
  5. Call validate_mesh to check printability
  6. Call export_model to save as STL, STEP, or other format

The key insight: the LLM sees rendered images of what it built. This visual feedback loop lets it catch mistakes and iterate, just like a human designer.

Example CadQuery code

Under the hood, the LLM writes code like this:

import cadquery as cq

result = (
    cq.Workplane("XY")
    .box(50, 30, 3)                    # base plate
    .faces(">Z").workplane()
    .rect(40, 20, forConstruction=True)
    .vertices().hole(4.5)              # M4 screw holes
    .faces("<Y").workplane()
    .transformed(offset=(0, 1.5, 15))
    .rect(50, 30).extrude(3)           # upright wall
)

You never need to write this code yourself. The LLM writes it, and the server executes it safely in a sandbox.

4. The Design Workflow

The server ships a design_workflow prompt that teaches the LLM the correct loop. The steps are:

  1. Execute — Write CadQuery code and run it via execute_cad
  2. Render — Always call render_views after every execute to see the result
  3. Critique — Examine the render and identify issues (wrong dimensions, missing features, visual problems)
  4. Revise — Fix the code and re-execute if needed
  5. Measure — Call measure to numerically verify dimensions
  6. Validate — Call validate_mesh to check printability
  7. Export — Call export_model to save the final model
Important The LLM must render after every execute. Without visual feedback, it can't tell if the geometry is correct. This is the core principle of cad-mcp.

Code modes

execute_cad supports two modes:

  • replace (default) — Replaces all code. Use for starting fresh or major changes.
  • append — Adds new code to the end of the history. Use for incremental modifications like adding holes, fillets, or cuts to an existing shape.

5. Tool Reference

execute_cad

Runs CadQuery Python code in a sandboxed subprocess. The code must assign its final shape to a variable named result.

  • code (string, required) — CadQuery Python code
  • mode ("replace" | "append") — Replace all code or append to history

Returns: solid count, bounding box dimensions, or a structured error with line number and hint.

render_views

Renders a multi-angle PNG preview of the model. Returns the image as MCP ImageContent (base64 PNG) that the LLM can see inline.

  • views (list) — Which views to render. Default: ["front", "right", "top", "iso"]
  • width, height (int) — Image dimensions. Default: 800x600
  • parts (list, optional) — Filter to specific parts in an assembly

validate_mesh

Checks mesh quality and printability.

  • min_wall_mm (float) — Minimum wall thickness. Default: 1.2
  • max_overhang_deg (float) — Maximum overhang angle. Default: 45
  • part (string, optional) — Validate a specific part

Returns: watertight status, manifold check, wall thickness violations, overhang report, volume, estimated PLA mass, and assembly interference warnings.

measure

Takes numeric measurements on the model.

  • what — One of:
    • "bbox" — Bounding box dimensions (x, y, z in mm)
    • "volume" — Volume in mm³
    • "faces" — Number of B-rep faces
    • "distance" — Distance between two faces (requires from_selector and to_selector)
    • "clearance" — Minimum distance between two parts (requires parts: ["a", "b"])

export_model

Exports the model to a file.

  • format — "step", "stl", "3mf", or "glb"
  • filename (optional) — Base filename (extension added automatically)
  • tolerance (float) — Tessellation tolerance for mesh formats. Default: 0.1 mm
  • parts — "all" (default), "active", or a list of part names

For multi-part exports: produces one file per part plus a combined assembly file. STEP assembly export uses XCAF with named shapes.

gen_ai_mesh

Generates an organic 3D mesh via the Meshy API. Requires MESHY_API_KEY environment variable.

  • prompt (string) — Text description of the shape to generate
  • art_style — "realistic" or "sculpture"
  • refine (bool) — Run a refinement pass for higher quality (slower)

create_part / set_active_part / position_part / list_parts / delete_part

Assembly management tools. See Multi-Part Assemblies below.

list_session / reset_session

list_session shows current parts, code history, and export history. reset_session clears all state.

ping

Returns pong. Takes no arguments. Worth knowing about because it answers from the server process itself: if a geometry operation has just crashed the kernel worker, a successful ping confirms the server survived it and the next call will get a fresh kernel.

6. Multi-Part Assemblies

cad-mcp supports designing models with multiple parts. Each part has its own code history, color, and position in the assembly.

Creating parts

Ask the LLM to create named parts:

You: Design a box with a lid. Make the box 60x40x30mm with 2mm walls, and a lid that fits on top with 0.3mm clearance.

The LLM will call create_part for each piece (e.g., "box" and "lid"), use set_active_part to switch between them, and write CadQuery code for each.

Positioning

position_part sets translation (mm) and rotation (degrees, Euler XYZ) for a part. Transforms are applied during render and export but not baked into the geometry, so you can reposition without re-executing code.

Colors

Parts are automatically assigned distinct colors (steel, blue, red, green, orange, purple) for easy identification in renders. Colors can be overridden via create_part(color="blue").

Interference & clearance

  • validate_mesh automatically checks all part pairs for interference (overlapping geometry).
  • measure(what="clearance", parts=["box", "lid"]) returns the minimum distance between two parts.

Exporting assemblies

When exporting multiple parts, export_model produces:

  • One file per part: model_box.stl, model_lid.stl
  • One combined file: model_assembly.stl
  • For STEP format: a single file with named shapes via XCAF

Limits

  • Maximum 16 parts per assembly
  • Part names: lowercase, starts with a letter, max 32 characters ([a-z][a-z0-9_]{0,31})
  • Backward compatible: sessions without create_part have an implicit "main" part and work exactly like single-part mode

7. AI Mesh Generation

The gen_ai_mesh tool generates organic 3D shapes (figurines, characters, terrain) via the Meshy text-to-3D API.

Setup

Set your Meshy API key as an environment variable:

export MESHY_API_KEY=msy_your_key_here

Usage

You: Generate a chess pawn figurine and place it on a 25mm square base.

The LLM will call gen_ai_mesh with the organic part, then use regular CadQuery via execute_cad for the parametric base, and combine them in an assembly.

Limitation AI-generated meshes produce tessellated B-rep geometry, not NURBS surfaces. Parametric operations like fillet and shell will fail on these shapes. Use them as-is or boolean-combine with parametric parts.

8. HTTP Transport

For remote clients, web UIs, or multi-tenant deployments, run the server over streamable HTTP:

uv run cad-mcp --transport http

Configuration

Environment VariableDefaultDescription
CAD_MCP_TRANSPORTstdiohttp for streamable HTTP
CAD_MCP_HOST127.0.0.1Bind address
CAD_MCP_PORT8000Bind port
CAD_MCP_AUTH_TOKEN(none)Bearer token for auth
CAD_MCP_CORS_ORIGIN(none)Allowed CORS origin
CAD_MCP_ALLOWED_HOSTS(none)Comma-separated allowed hostnames. Deny-by-default off loopback, so list the hostnames clients actually send or every request is rejected.
CAD_MCP_PUBLIC_URL(none)Required off loopback. The origin clients actually reach, e.g. https://cad-mcp.example.com. The bind address is not a URL: without this, a server on 0.0.0.0 advertises http://0.0.0.0:8000/mcp as its OAuth resource URL.
CAD_MCP_STATELESS01 for stateless HTTP mode. Not a way to avoid session affinity — it breaks the core loop, because render_views reads state execute_cad wrote.
CAD_MCP_SESSION_IDLE_TIMEOUT_S300Seconds an unused session is kept before eviction
CAD_MCP_OUTPUT_DIR./cad-mcp-outputWhere exports are written — outside the session temp dir, which reset_session deletes

The README lists every variable the server reads, including the sandbox, geometry-kernel and rendering knobs.

Running it hosted

There is a Dockerfile and a fly.toml in the repo, plus a deploy workflow and a smoke test that drives the full core loop over the wire. Because MCP's streamable HTTP transport is stateful — parts, code history and the cached .brep live on one machine's disk — a multi-instance deployment needs session affinity, which the server establishes itself. See docs/deploy.md.

Authentication

When CAD_MCP_AUTH_TOKEN is set, all MCP requests require Authorization: Bearer <token>. Requests without a valid token get HTTP 401. The health endpoint (GET /health) is always accessible without auth, and reports readiness rather than liveness: 503 while the geometry kernel is still importing CadQuery, then 200 with the active render backend.

9. Prompts & Resources

MCP Prompts

The server ships three prompts that the LLM can invoke to learn how to use the tools:

  • design_workflow — The core design loop. Mandates rendering after every execute and self-critique before export.
  • cadquery_primer — A CadQuery cheat sheet covering Workplane basics, extrude/cut, fillets (with failure modes), shell, hole patterns via polarArray, and booleans. Each section has a runnable snippet.
  • printability_checklist — FDM printing guidelines: minimum wall thickness, overhang angles, bed adhesion tips, and tolerances for mating parts.

MCP Resources

  • cad://session/current/code — The full CadQuery source code of the current model. Useful for recovery after context loss.
  • cad://examples — An index of the curated examples, one line each. A concrete resource, because a client that only lists concrete resources would otherwise never discover the templated one below.
  • cad://examples/{name} — Curated example models the LLM can study. Available: bracket, enclosure, flange, pipe_clamp, phone_stand, threaded_cap, gear, desk_organizer.

10. Troubleshooting

CadQuery / OCP installation

pip/uv install fails with "no matching distribution"

CadQuery requires cadquery-ocp, which ships pre-built wheels for Python 3.10–3.13 on Linux x86_64, macOS x86_64/arm64, and Windows x86_64. If your platform isn't covered:

# Check your Python version
python --version

# Use a supported version via uv
uv python install 3.11
uv sync

macOS Apple Silicon — OCP build errors

cadquery-ocp wheels are available for arm64 since cadquery 2.4. If you still hit issues:

# Ensure you're not running under Rosetta
arch  # should print "arm64"

# Use a clean venv
uv sync --reinstall

# Or install via conda-forge
conda install -c conda-forge cadquery

Segfault on exit (exit code 139 / 0xC0000374)

OCP tears down OpenCascade's static destructors at interpreter exit and sometimes crashes doing it — after all the real work has completed and been written. Two things now handle this, so you should not see it:

  • The server runs OCP in a separate long-lived worker process, so a kernel fault becomes a structured tool error and the server keeps answering. Set CAD_MCP_GEOMETRY_ISOLATION=0 to turn that off for debugging and the crash comes back, taking the server with it.
  • The test suite flushes and hard-exits, skipping the destructors, so pytest's exit code means what it says.

Rendering

pyrender / EGL not available

The server automatically falls back to matplotlib 3D rendering when pyrender + EGL is unavailable (common on Windows, CI, and headless servers). The fallback produces correct multi-view images with axes and scale ticks.

To enable the faster pyrender path on Linux:

# Install EGL libraries (Ubuntu/Debian)
sudo apt-get install libegl1-mesa-dev libgles2-mesa-dev

# On headless servers without GPU, use Mesa's software renderer
sudo apt-get install libosmesa6-dev
export PYOPENGL_PLATFORM=osmesa

Render takes > 2 seconds

The first render pays a one-time matplotlib font cache initialization cost (~1–3s). Subsequent renders should be well under 2s.

Validation

trimesh warns about rtree

The wall-thickness check uses scipy KDTree, not trimesh's ray casting, so rtree is not required. The warning is safe to ignore.

manifold3d API errors

This project requires manifold3d ≥ 3.5.2. The correct API is:

import manifold3d
mesh = manifold3d.Mesh(vert_properties=verts_f32, tri_verts=faces_u32)
m = manifold3d.Manifold(mesh)
print(m.status())  # Error.NoError for valid manifold

CI issues

Do not work around the exit code. Older advice here suggested grepping pytest's output for “passed” instead of trusting its exit status, because of the OCP shutdown segfault. That is no longer true and was never safe — it turns a crashed run into a green one. The suite hard-exits after flushing, so the exit code is correct, and CI relies on it directly:

uv run pytest -q                       # everything except live LLM tests
uv run pytest -q -m serial -n0          # wall-clock budgets, un-contended

Wall-clock tests fail on a busy machine

Tests marked serial assert how fast a timeout fires or count processes on the host, which measures the machine rather than the code when other work is running. Run them with -n0 on an idle machine. The default selection already excludes them from the parallel run.
